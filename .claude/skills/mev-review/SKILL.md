# MEV复现审查流程

强制按阶段顺序执行,禁止跳步。每阶段有明确的完成标准。

## 阶段1 — 理解与假设暴露
1. 用自己的话复述问题(一段话),让用户确认理解无偏差
2. 列出本任务最可能出错的 **3个隐含假设**,例如:
   - "fork块高的state等于交易执行时的state"(同块前序交易可能改变state)
   - "wstUSR的汇率在复现时段内不变"(rebase/depeg期间恰恰在变)
   - "事件日志一致=执行一致"(中间state可以不同)
3. 标注哪些假设本任务必须先验证,哪些可以暂时接受

**完成标准:** 假设清单已列出且用户/上下文确认了问题理解。

## 阶段2 — 取证(固定顺序:trace → 状态 → 代码)
严格按此顺序,禁止先读代码再"确认"trace(会产生确认偏误):
1. **Trace层:** 拉取目标交易完整trace(`cast run <tx> --trace` 或等价物),记录call树、每步gas、关键SSTORE/SLOAD
2. **状态层:** 检查涉及合约在执行前一刻的真实state(块高、slot值、余额、汇率)
3. **代码层:** 最后才读合约代码,且必须读**链上实际部署的字节码对应版本**(proxy要解到实现合约)

推荐命令序列(按需替换):
```
cast run <txhash> --trace --rpc-url $RPC
cast storage <proxy> <slot> --block <N-1>
cast call <contract> "getRate()" --block <N-1>
```

**完成标准:** 三层证据都已落盘(存到文件,不只是看一眼),diff点已定位到具体call或slot。

## 阶段3 — 验证(结论必须可机械检查)
每个结论逐条过以下检查,任何一条不过就回到阶段2:
- [ ] trace diff:复现trace与链上trace逐call对比,差异为零或每处差异有解释
- [ ] gas一致性:总gas与关键子call的gas在容差内一致
- [ ] 终态一致:所有被触碰账户的余额/slot终态与链上一致
- [ ] 数值精度:所有汇率/金额换算标注了舍入方向,与合约实际逻辑一致
- [ ] 反事实检查:如果结论是"X导致了差异",移除/修正X后重跑,差异应消失

**完成标准:** 上述清单全过,或明确列出未过项和原因。

## 阶段4 — 汇报格式
- **结论**(一句话)
- **置信度**(高/中/低 + 理由)
- **证据索引**(每个结论 → 对应的命令和输出文件路径;展示证据而非宣称成功)
- **未排除的替代解释**(哪怕觉得不太可能也要列)
- **建议写入decision-log的条目**(如有新决策)

## 审查纪律(审查他人工作时)
- 只标记**影响正确性或既定需求**的差距;风格偏好、假想边界情况、防御性建议一律标注为"可选",不计入diff
- 审查者天然倾向于报出问题以证明自己在工作——不要为了产出发现而制造发现
