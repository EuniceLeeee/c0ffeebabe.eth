一、三个边界
------------

1. Family = selector + 规范化完整函数输入 ABI。
   输入类型、顺序、tuple 和数组维度参与身份；协议名不参与。
   同一个合约可属于多个 family；同一个 family 可有多个执行 program。

2. 作者写 selector-family/v2 JSON。
   单个简单执行规则直接写 selector、signature、parameters、payment。
   单规则不需要 programs 外壳；缺省 format 是 v2，缺省 domain 是 swap。
   ABI 中拿不到、而 SQL 资金流也不能唯一确定的数据，才需要 binding。
   同一 ABI 的多种付款或结算规则使用 programs；复杂执行才需要 execution。
   callback 继续放在 execution 的 frame/settlement/deferred 数据里。
   价格优先使用现有启动模拟；作者不需要再填一份重复的 simulation-first 配置。

3. 共用 TS 生成完整运行对象。
   新的公开入口是 defineSelectorFamilyModule(definition)，只发布
   selectorFamilyModule。生产装载器验证 v2 品牌和定义；旧 JSON 格式、旧的
   plugin/activation/productionFamilyModule 导出不能被当作新模块装载。
   内部共享的执行、定价、风险和回执接口保留实际管线需要的完整语义。

二、最小声明与必要扩展
--------------------

可直接校验并构造的新模板位于 examples/selector-family-v2/：
  minimal-swap.json
  minimal-redeem.json
  minimal-swap.module.ts

minimal-swap 是真实本地 EVM 管线测试使用的 ABI，具有 poolId、两个 token、
输入金额、最低输出和 recipient 参数。它不声明 binding、routes、execution
或 observations；共用 TS 自动绑定、生成 route、编译付款和实际余额检查。

minimal-redeem 说明 shares/receiver/owner 参数角色。其 token pair 必须来自
已明确的候选交易资金流；若缺失或冲突，要补必要 binding，不能猜资产方向。
它是框架最小模板；生产目录中的复杂 redeem 还保留原 Exact 的必要返回值、
余额和供应量约束。

可选扩展与用途：
  binding     执行必需的 getter/状态读取、不可变参数和资源绑定。
  routes      不能从参数或唯一候选方向推导的方向及物理资源。
  execution   多步调用、amountOut/maximum-input、native、callback、精确结算。
  ethCall     可选报价方法；不能将失败 SIM 伪装成执行通过。
  observations  已有事件识别/刷新能力；最小 swap 不再强制提供事件。
  dependencies  共享状态变更时必须刷新报价的额外地址；物理资源放在 routes。
  meta        名称、identity 标签、来源和说明；不进入运行语义指纹。

执行会用到的 poolId、tokenId、物理资源、回调支付、费用、还款、守恒和刷新
依赖不能挪进 meta。能由共用 TS 推导的部分自动生成；剩下的必要语义才留在
作者 JSON 中。缺失的语义会明确保持 incomplete/unverified。

四、Ready、Graph、价格和 touched
-------------------------------

SQL/census 先保留全部观察；已知 ABI 和执行规则产生 candidate。
Ready 在新 family 下绑定 target、参数、资产和 pool 资源，再生成候选 graph。
最小普通声明可以没有池子 identity RPC，也无需在 Ready 重做价格 SIM。
数据不完整时，只按 JSON 中实际必要的绑定声明读取；credit 的主动 position
证明保留原有专用行为，不能降级为普通 swap。

候选/route 身份包含：
  chainId、selector + canonical input ABI、target、poolId/namespace、
  有序 tokenIn/tokenOut 地址与 tokenId、不可变参数、program 与方向。

同地址的不同 selector、poolId、方向和规则不会被地址去重吞掉。
同 ABI 的多个 program 按完整 candidate 重新解码匹配唯一 pattern，严格证明
使用选中的 pattern；不会退回第一套规则。

执行身份与物理资源分别保存：两个程序若使用同一真实池，仍会共享资源冲突
和 touched 刷新范围。Curve 的 basePool 等实际只读依赖也会触发价格失效。
未配置事件的最小 swap 不发布虚构的事件/victim 能力；它仍保留地址/资源触达。

启动表带资金准备的同一次模拟提供：是否 revert、实际 amountSpent、实际
amountOut、当前 source/block、executor、输入金额和脚本/回执证明。
已成功模拟的价格不为启动 revert 筛选再跑一遍。

随后沿用 effective → 自然枚举 → Exact/金额求解 → 交易编译 → 最终 SIM →
还款、余额和 EV 检查。候选 edge 本身不是已验证价格；历史交易成功也不能
充当当前 executor、新金额或新 source 的执行证明。

本轮不再使用旧 identity 选择 family；仍需要执行所需的 getter、当前状态读取
和模拟节点。普通 live 定价与执行不增加 trace RPC 依赖。

五、Funding 与 credit
-------------------

Funding 同样按 selector/ABI + provider + 资产/池范围绑定：
  0x5c38449e：实际当前费率、向上取整、转账偿还本金和费用。
  0xe0232b42：保留原零费用语义、精确授权、provider 拉取本金。

回调 caller、selector、参数、children 字节、实际借款和偿还继续受校验。
同一 holder 的真实余额不会因多个 selector/逻辑池而重复计算为独立流动性。

价格表和资金准备共用 SEARCHER_EFFECTIVE_MAX_INPUT_PATH_HOPS。
从 4 改成 6，允许的准备路径随之变化，旧价格/完成记录也按新策略失效。
它是资金准备路径上限；目标报价调用另行执行，没有固定写死四跳。

Credit 的 0x032d2276 完整保留配置/oracle、整数风险数学、主动 new-position
证明、实际 collateral/debt effects、standing-position 和最终还款门禁。
131 个独立整数边界向量与 fdb859a 的原数学实现逐项一致。

六、SQL 直接导出 edge
--------------------

ready-discovery-udf.sql 同时输出 candidate、selector-census 和 selector-edge。
ready-bigquery.mjs 在输出目录写 selector-edges.json。
它是 Ready admission 前的有方向观察清单，便于与正常 graph 对比。

完整绑定按执行身份去重；未知 selector、只识别 ABI 而没有规则、参数未明确
的记录仍保留原始 calldata/source/callId。不会因两个 token flow 都存在就提前
合并未知参数。生成这份清单不需要 RPC 或模拟；对比工作留给使用者。

本包包含构建好的浏览器 UDF 资源和相对路径构建清单。上传/查询仍使用你已有
的 BigQuery 配置，不在交付中放账户凭据。

八、升级时的状态边界
------------------

这次是明确的 v2 格式切换。旧 family JSON/TS 不能通过新生产入口继续装载。
旧 Ready 证明、旧候选和旧 effective 缓存需按新定义重新生成；新运行时不会把
旧版本的成功标记当作 v2 执行授权。

同一 v2 内仅修改 meta，不改变 candidate、program、route、Ready 或能力的
语义身份。原始文件审计 SHA 仍变化，生成器会要求刷新产物完整性记录。
fdb859a 的同版本 subset/resume、source/hash、settlement 证据和最终模拟检查
继续保留，并有回归覆盖。
