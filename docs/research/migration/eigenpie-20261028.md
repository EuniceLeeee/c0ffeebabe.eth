## Gaps / deviations (all fail closed)

G1. Unresolved identity results: `declarative-identity.ts:104-106` throws the typed
`RequiredAdapterRequestError` before the family decode, so the TS wording
"Eigenpie identity unresolved: <failure>" (`eigenpie-family/identity.ts:134-139`) cannot be reproduced
from JSON. Semantics are identical (required result unresolved ⇒ fail closed). The offline assertion
`test/eigenpie-family-identity.ts:274` was relaxed to `/unresolved|required adapter request/`; the suite
passes 32/32 against both the TS family and the declarative definition. Residual engine wording-only gap;
no framework change requested.

G2. Discovery nomination breadth: mapped discovery uses `createTxEvidenceNomination({allMatches:true,
acceptObservation})` (`declarative-discovery.ts:214-218`), i.e. every matching observation per transaction,
where the TS nomination returned the first match per pattern (`discovery.ts:103-121`). Candidate admission
is unchanged (identity still proves behavior); only more nominations per tx are offered.

G3. Candidate shape: `FieldSource` has no null/hash source (`declarative-discovery.ts:19-23`), so
call-derived candidates carry `observedAmountOut: 0` plus `hasObservedAmountOut: false` instead of
`null`/`transactionHash`. The decide rule enforces the observed output equality unless the flag is
literally `false`, so a missing flag cannot skip the check. `transactionHash` is unused for admission.

G4. Candidate key encoding: `JSON.stringify([target, tokenIn])` (`declarative-discovery.ts:222-232`) instead
of `target:tokenIn`. Same equivalence class; route/instance keys come from `identity.subject` and are
byte-identical to TS.

G5. Runtime projection: `declarative-protocol.ts:509` fixes `NO_EXECUTION_RUNTIME_PROJECTION`; the TS
family declared `hopTargetExecutionRuntimeProjection` (`execution.ts:27`, `allowanceSpender = target`).
That projection is only a revm quote-simulation pre-approval hint; the declarative leg performs its own
approve/clear, so execution authority is unchanged (slightly colder quoting).

G6. Settlement: the declarative execution contract requires `settlement.directOutput`
(`declarative-execution.ts:113`). The deposit mints to `msg.sender`, so `false` is declared with an
external-recipient context check; a direct-output settlement is declined (`buildDeclarativeRuntimeLeg`
returns null) instead of producing a fragment whose receipt cannot be redirected.

G7. Supply positivity: the declarative `supply` effect has no implicit positive bound
(`declarative-execution.ts:191-199`); `minimum: 1` preserves the TS `total-supply-delta increase` fact.

G8. `protectedAddresses` is `[target, asset, receipt]` instead of the TS `[target]` (strictly narrower
executor admission; an executor can never be one of these tokens).

G9. The pricing descriptor carries `routes` because `pricing.current.decodeSnapshot` reads
`descriptor.routes` (`declarative-protocol.ts:356-361`); the TS pricing draft had no `routes` field.

G10. Family-local request ids differ (`current-mlrt-quote`, `quote-mlrt` vs TS `current-quote`,
`exact-quote`); ids are not part of snapshots, evidence or cache compatibility projections.

G11. `standard.pricing.dependencies`/`mutationAddresses` are evaluated with the pricing descriptor, so the
route assets are addressed as `$descriptor.route.tokenIn|tokenOut` (TS used
`descriptor.route.tokenIn|tokenOut` too).

Async claim: the family exposes no claim/queue route. `AssetDeposit.isPreDeposit = true` (the pre-deposit /
delayed-mint form) is rejected by the discovery predicate, exactly as in `discovery.ts:79`; no delayed
claim is projected as an immediate asset and no route was added or removed.
