## Deviations / fail-closed shapes

1. **Candidate identity key**: mapped candidates require an address field, so `subject` is the real
   Router/Core target/emitter and the candidate key is `[subject, poolId]`; the identity subject stays
   the `poolId`. Nomination grouping differs; admission is unchanged.
2. **Retained path provenance**: cold rows are admitted from the persisted `routeBinding` + behavior
   proof, not from a fresh Core `PoolInitialized` log. A raw retained row that carries only `poolId`
   (no `routeBinding`) still needs the legacy Core-log index; the production `PoolUniverseEntry` path
   carries `routeBinding`, and the retained `ekuboPoolDiscovery` completes retry rows before they enter
   the universe.
3. **Multihop chain strictness**: fan-out yields one candidate per hop but cannot fold the carried token
   chain across items; a malformed non-chaining multihop call would nominate each hop, each of which
   still passes full identity. Every hop's zero-limit/initial-amount predicates are declared.
4. **Pricing shape**: the flow always performs a third (possibly empty-request) retry round; the
   snapshot is per pricing group (`quotes` keyed by routeKey) rather than the legacy per-direction
   object, and `liveStateProjection` publishes the group snapshot. Graph mid/depth/reserve/fee match.
5. **Mutation index**: anonymous Core logs invalidate all Ekubo routes on that Core address instead of
   only the matching `poolId`; conservative over-invalidation.
6. **Native-output `directOutput`**: the common capability projection withholds `directOutput` when the
   route output is native; ordinary executor receipt still works and external native output returns
   `null` (fail-closed) where the handwritten family threw.
7. **Execution shapes**: fragment requirements are the shared empty list and the node carries a
   `runtimeAmountProgram`; the program itself performs the allowance/approval and router-delta checks.
   Fragment/action calldata shape therefore differs from the handwritten node params.
8. **Route/deposit shapes**: routes include `isToken1/poolId/poolKey` fields and the common
   `target/direction/adapterId`; pricing dependency lists are framework-sorted/lowercased.
