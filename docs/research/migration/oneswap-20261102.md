## Deviations / fail-closed shapes

1. **Route address casing**: the common route projector applies `getAddress` (`declarative-family.ts:251`),
   so `tokenIn`/`tokenOut` are checksummed; the retained test expects lowercase. Route keys and
   binding fingerprints still use lowercase where the legacy family did.
2. **Exact evidence** uses `retainReadEvidence`: quote components needed for execution are recomputed
   from the stored source-bound read results rather than trusted as data. This is why the legacy
   contract test's hand-built evidence is rejected; it is a stricter evidence boundary.
3. **Fragment node shape** is the shared `{runtimeAmountProgram}` shape, not the legacy
   `{rawIn,rawOut,factory,implementation,executor,minimum}` params. Action encoding is the shared
   program script (`encodeRuntimeAmountNode`).
4. **Native output direct settlement** with an external recipient returns `null` from
   `buildRuntimeLeg` (common capability projection) where the handwritten family throws; both fail
   closed before execution, and `directOutput` is still only advertised when safe.
5. **Zero/limit state**: `pricingFlow` classifies a route whose sampled depth is zero or whose quote
   is zero as unavailable with an explicit reason. The handwritten path silently omitted the mid;
   no price, fee or capacity is invented.
6. **`liveStateProjection`** exposes the declarative snapshot (state + quotes + rows + unavailable)
   rather than exactly the handwritten `{sells,buys,...}` shape; graph mid fields match.
7. **State read model** delegates to `decodeState`, including the `IMPLEMENTATION_HASH` re-check on
   every read. Synthetic offline code bytes therefore cannot pass this check (verified fail-closed);
   full read-flow/exact/execution acceptance still needs a real same-state sample.
8. Route objects carry the common `target`/`direction`/`adapterId` fields in addition to the legacy
   `pool`/`buy`, so route hashes differ even though keys/tokens/assets match.
