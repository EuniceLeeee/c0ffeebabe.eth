  `olympus-staking-surface` fingerprint `olympus-staking-v3-unstake-v1`; candidate `olympus-staking`

- Identity: two stages. `surface` reads runtime code + `OHM()`/`gOHM()`; `tokens` reads gOHM/OHM code

## Deviations (fail-closed or structural; no weakened checks)

1. Exact evidence carries the shared `readProof` (`retainReadEvidence`), so execution re-decodes the
   read flow instead of trusting consumer-supplied fields; amount/outcome checks are unchanged.
2. Quoted execution nodes carry `params.runtimeAmountProgram`; the declarative action adapter re-emits
   that shared program (`0x0e` script) instead of the handwritten hand-encoded CALL list. The decoded
   call (`unstake` with recipient/amount) and checks are the same, but the plan bytes differ.
3. The shared execution compiler adds (a) an `unchanged-native` inventory check around the leg and
   (b) before/after balance captures for every effect. Both are stricter than the handwritten direct
   program and never over-quote.
4. The pricing descriptor gains the declared `routes` group (the shared snapshot validator reads
   `descriptor.routes`). Every handwritten pricing field is otherwise identical.
5. The exact method's `trialState` is reported as `{ unsupportedReason }` from the local-math quote
   flow instead of being omitted; positive inputs are still rejected before any quote.
6. Rejection wording differs in two fail-closed paths: non-empty runtime evidence now throws the
   shared "declared pending execution unsupported" (was "does not accept external evidence"), and a
   mismatched quoted amount in the retained read proof throws "execution read proof amount mismatch"
   (was "incompatible exact evidence").
7. No `types` block is declared, so central generation will produce an untyped production entry (the
   schema makes type metadata optional; no generated type artifact is created here).
