## Fail-closed / legacy-shape deviations

1. **Discovery sources**: `factory-log` is not in the mapped-discovery enum; `observed-call` has no
   declarable tuple-argument mapping, so the `PoolManager.swap` call pattern is not declared (mapped
   `from:"argument"` cannot address tuple components, `declarative-discovery.ts:152-177`), and the
   Swap-domain `calls` block is omitted for the same reason (`declarative-swap-domain.ts:41-52`), so
   pending `PoolManager.swap` calldata observation is not migrated. New pools are nominated from
   `Initialize` logs and retained graph entries from the address surface. The handwritten
   recent-Swap-log/trace nomination (`univ4-family/nomination.ts`, `trace-evidence.ts`) is replaced by
   the address-surface read flow; identity still re-verifies the PoolKey hash, manager code and active
   state at the source block.
2. **Reverse binding**: declarative discovery hard-codes `explicitly-unsupported`
   (`declarative-discovery.ts:92,308`); retained binding is carried by the address-surface read flow
   instead of the plugin implementation (`univ4-family/reverse-binding.ts`).
3. **Negative `tickSpacing` pools are not discoverable**: mapped discovery scalar `uint` accepts only
   non-negative values (`declarative-discovery.ts:104-115`); identity asserts the int24 upper bound but
   a negative spacing rejects during candidate decoding. Positive-spacing pools are unaffected.
4. **Exact amount class**: a quoter revert and the manager output-balance capacity failure throw
   ordinary errors instead of `ExactAmountRejectedError` (`univ4-family/exact.ts:87,98`); the solver
   aborts the quote instead of treating the amount as rejected. `gasEstimate` is not declarable
   (fragment re-derives evidence and compares hashes, `declarative-family.ts:745-749`) and is dropped.
   A positive-input quoter output of zero is rejected by the chain-proof positivity rule
   (`declarative-quote-proof.ts:89-91`) instead of returning zero evidence; the zero-input local method
   keeps the zero quote.
5. **Pricing telemetry**: rows carry integer ratio/depth/fee (whole-bps floor). The graph mid,
   reserves, depth and integer fee match; the `v4` mid kind, `sqrtABX96` and `liquidity` telemetry
   fields are not representable (`declarative-pricing-projection.ts:19-30`). Odd `lpFee` values lose
   sub-bps precision in `feeBps` only.
6. **Deferred-input settlement not migrated**: the handwritten runtime program supports
   `deferred-input` (`univ4-family/runtime-execution.ts:32-43,70-95`); the declarative declaration
   publishes only `directOutput` and the common runner rejects deferred input without a real framed
   settlement test (`declarative-execution.ts:826-841`). This is a capability narrowing, not a
   weakened check.
7. **Native direct output**: production declares `directOutput: true` but returns `null` when a native
   output request has an external recipient; declarative capability projection withholds
   `directOutput` for native outputs (`declarative-execution.ts:842-853`). Executable set is the same.
8. **Swap pool identity**: the `Swap` event binds the manager target and selects the direction with
   `$descriptor.poolId` (when the receipt provides a resolved binding); the handwritten observer keys
   the same event by `poolId` and `edge.v4PoolKey`. A receipt path without a binding reports the event
   as mutation-only (fail-closed) rather than borrowing another pool's key.
9. **Mutation fan-out**: declarative mutation indexing is address-based; the declaration filters the
   manager log by topic and `poolId` in `pricing.mutationPredicate` instead of the TS map built in
   `univ4-family/pricing.ts:225-243`. Behaviour is equivalent; dependency address casing/order is
   normalised by the common layer.
10. **Victim replay `bind` shape**: declarative replay returns the bound `routeKey` (the common
    contract, `declarative-swap-domain.ts:230-241`), not the route object.
11. **Landed/receipt event set is a superset**: the declarative compiler makes every declared event an
    owned trigger (`declarative-swap-domain.ts:88-115`), so `Initialize` is classified as a mutation
    on receipts in addition to the handwritten swap/modify set (`univ4-family/swap.ts:29-41`). It is
    never treated as a swap; more receipts are classified, no check is dropped.
12. **Static pricing stage**: the family has no static pricing phase; the declaration uses an explicit
    dependency-free `source-local` stage with zero requests (`pricing.static`). It issues no RPC and no
    dependency proof.
13. **Pricing descriptor shape**: the pricing draft carries the projected `routes` so the common
    read-flow can rebuild its dependent precision round at decode time (the framework reconstructs the
    flow from the pricing descriptor). This is an in-memory shape addition; the published graph mid
    fields are unchanged.
14. `poolMaterialization` is declared with the common `{observation}` input; the reference exits with
    `null` for non-`Initialize` observations.
