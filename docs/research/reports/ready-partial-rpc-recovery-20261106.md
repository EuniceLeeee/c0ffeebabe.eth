# Partial RPC read recovery in Ready

At historical block 26,222,895, seven exits in the cached Ready run had seven distinct candidate keys. The last two traversals stopped at 129,298 and 130,482. The failed methods were a storage read on the EtherToken native redeem candidate at `0x5b75c60d45bfb053f91b5a9eae22519dfaa37bb6` and the chain-ID precheck while evaluating the ERC4626 candidate at `0x31558b4efa1dd8e1997eb91a820c044da6386d97`. The former had a correlated HTTP 200, JSON-RPC -32000 Internal error. The latter recorded code -32000 and method eth_chainId, but the old relay did not save that method's message or error-data shape.

The Ready transport retains successful replies and resends only the requests that returned a plain -32000 Internal error without error data. Request IDs, parameters, pin and the existing three-attempt budget are preserved. The source precheck supplies its expected chain, height and hash so that a successful sibling is checked against the actual pin before retention. The caller still validates the complete batch and compares the canonical headers. Contract execution calls, live mode, bridge pre/post checks, source mismatches, quota and revert handling keep their existing policy. Exhaustion is observable and still fences the source.

Two real candidate replays used the same pinned state and ordinary production identity entry. In controlled 8-item state and 3-item precheck batches, the old binary failed on one injected error. The new binary retried only the failed item in each batch and returned the same terminal rejection as the corresponding uninjected control. This establishes transport recovery, not admission of either pool. The initial state relay experiment closed a connection before fault injection due to an empty-params bug in the test relay. That attempt was retained and excluded from the comparison. The release build and all 111 Rust tests passed, including malformed sibling, ID substitution, wrong chain/hash, exhaustion and multi-round partial reads.

The operator retains the original checkpoint, journal and freezes. Fixed-run resume uses its sealed candidate partition and does not decode the earlier 162,174 nominations a second time. The loader still validates the on-disk checkpoint and journal. Base recovery runs in its own service, and the monitor reserves bounded whole-job restarts for positively classified, exhausted internal state-read errors. The same candidate cannot repeatedly restart a stage, and two source restarts per stage per half hour is the ceiling. The earlier monitor's exit also ended its in-group checkpoint loader without an exit marker. The owned stale lease is recoverable after proving both owner processes have exited.

This change is scoped to Ready reliability. The intended dry-run remains the oct29 set of 36 Families and 500 blocks after price publication. No live performance or full-window result is inferred from these controls.
