## Design (mirrors A5 wstETH structure — reuse it)
### Taxonomy (A0, done): ERC4626 deposit → `protocolAction:"wrap"` (share entry, full-value, unguarded);
redeem → `protocolAction:"redeem"` (unguarded). NOT `"mint"` (mint = debt; ERC4626 shares are an asset).
Both are in the STANDING-SAFE set ⇒ `leavesStandingPosition:false`. Confirmed consistent with
`deriveEdgeTaxonomy`.

### 1. New execution adapter `listener/src/adapters/erc4626.ts`
- `erc4626DepositAdapter` (id `erc4626-deposit`): `deposit(uint256 assets, address receiver)` — receiver
  rewrite = executor; `assets = node.amount`. Approve the asset to the vault.
- `erc4626RedeemAdapter` (id `erc4626-redeem`): `redeem(uint256 shares, address receiver, address owner)`
  — receiver = owner = executor; `shares = node.amount`. No approval (burns the executor's shares).
- Register both in `adapters/index.ts`.

### 2. Graph `token-graph.ts`
- `PoolEntry.adapter` union: add `"erc4626"`. New `case "erc4626":` in `queryPoolEdges` emitting BOTH
  edges per vault (deposit asset→shares `erc4626-deposit` action `wrap`; redeem shares→asset
  `erc4626-redeem` action `redeem`), per-edge adapterId (like the A5 wsteth case). The registry entry
  carries `fixedTokenIn`(asset)/`fixedTokenOut`(shares/vault token) so no on-chain token query is needed.
- POOL_REGISTRY entries for sUSDS (asset USDS ↔ shares sUSDS) and wstUSR (asset ↔ wstUSR), once addresses
  are verified.

### 3. Quote `quoter.ts`
- `quoteErc4626(state, target, tokenIn, tokenOut, amountIn)`: deposit direction (tokenIn==asset) ⇒
  `previewDeposit(amountIn)`; redeem direction (tokenIn==shares) ⇒ `previewRedeem(amountIn)`. Read via
  `state.call`. Dispatch `case "erc4626-deposit"` / `case "erc4626-redeem"`.
- Later (deferred): local NAV math to avoid the eth_call (plan's "previewDeposit/previewRedeem, local
  math later").

### 4. plan-builder `plan-builder.ts`
- `case "erc4626-deposit":` approve asset, node.amount = amtIn (assets). `case "erc4626-redeem":` no
  approve, node.amount = amtIn (shares).

### 5. Template: add `"erc4626-deposit"`, `"erc4626-redeem"` to `SWAP_ADAPTERS`.

### 6. Offline gates (once addresses land): a planner flip fixture (synthetic vault-share DEX venue to
close the loop) + a `searcher:erc4626-quote` mocked unit (previewDeposit/previewRedeem) + a calldata
unit. Fork-sim (NAV round-trip on sUSDS + wstUSR) = operator gate.

## Loop-closure note (same as A5)
An ERC4626 deposit/redeem edge only closes a loop if a DEX venue for the share token OR the asset is in
the graph (e.g. Curve sUSDS pools — `ADDR.CURVE_SUSDS_USDT`, `CURVE_DOLA_SUSDS` already exist! so sUSDS
has in-graph return venues; wstUSR has `CURVE_DOLA_WSTUSR` + the Fluid credit edge). sUSDS is the
strongest instance — its Curve return venues are already indexed. **Prioritize sUSDS.**
