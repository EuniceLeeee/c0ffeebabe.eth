请执行本项目的蒸馏压缩,严格按以下步骤:

<!-- 核心步骤1-6每次必做;7-8为周期项,当天记录少可跳过,但不得连跳两次 -->


1. **读取今日新增:** 读 `docs/distill/` 下今天日期的所有对比记录。

2. **规则去重与合并:**
   - 对照 `CLAUDE.md` 领域规则区和 `mev-review` SKILL.md 的失败模式清单
   - 今日新规则与已有规则语义重复的 → 合并,保留更精确的表述,来源编号合并标注
   - 多条规则指向同一根因的 → 合并为一条更通用的模式

3. **证伪清理:**
   - 检查各对比记录第5节的回归验证结果,标记"无效"的规则从CLAUDE.md/SKILL中删除
   - 检查是否有今日证据推翻了更早的规则或decision-log条目,有则更新状态(❌划掉,不删)

4. **结构升级判断(重要):**
   - 今日的「路径差」是否暴露了SKILL四阶段流程本身的缺陷?
   - 如果同类路径差出现≥2次 → 修改阶段定义或阶段顺序,而不是再堆一条规则
   - 说明你做了什么结构改动及理由

5. **范例与复查题甄选:**
   - 今日记录中是否有值得升级为worked example的完整推理过程?有则按SKILL末尾格式写入
   - 今日是否有"Opus答砸、Fable答对且可客观核对"的题?有则按GOLDEN-SET格式
     冻结进复查题集(题目原文+Fable答案+代码锚点+评分口径)。题集满8题后停止新增。

6. **体积纪律:**
   - CLAUDE.md超过80行 → 必须压缩:低频规则降级到SKILL,或合并
   - SKILL.md超过300行 → 失败模式清单归并,旧范例淘汰(保留最多2个)

7. **框架元审查(每日执行,审容器不审内容):**
   - TEMPLATE字段是否漏捕了某类差距?(出现归不进四层diff的差异 → 提议加层)
   - 四个文件的分工边界是否有内容反复放错位置?→ 提议修改分工定义
   - 是否有差距"记录了但没有去向"?→ 说明框架缺了哪个出口
   - **修改约束:** 每处改动必须引用≥2条具体记录编号作为动机;不变量不许动:
     四层单向信息流、CLAUDE.md体积上限、结论与模式分离、raw/永不删除。
     改动以diff形式输出,经用户确认后执行,并在被改文件头部升级版本号。

8. **源数据完整性检查:** 核对今日每条对比记录的"原始记录路径"字段,
   确认对应jsonl已归档到 `docs/distill/raw/`。缺失的列出提醒用户补archive。
   同时检查:今日的trial/*分支是否已按BRANCH-PROTOCOL收尾删除;
   今日规则库若有实质更新,REGRESSION-TREND是否安排了回归轮次。

9. **输出压缩报告:** 新增_条 / 合并_条 / 删除_条 / 结构改动提议_处 / raw归档缺失_个 / 当前CLAUDE.md行数。

不要跳过第6步。规则库的价值在于Opus真的会读,膨胀等于失效。
